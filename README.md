# Personal Financial Manager

[![Tests](https://github.com/Roma4286/PersonalFinancialManager/actions/workflows/test.yml/badge.svg)](https://github.com/Roma4286/PersonalFinancialManager/actions/workflows/test.yml)

A REST API for personal finance tracking: wallets, income/expense categories,
transactions, and transfers between wallets. Built with **NestJS**, backed by **PostgreSQL**,
with data access via **Kysely** (types generated from the Prisma schema), and API docs via **Swagger**.

## Stack

- NestJS + TypeScript
- PostgreSQL
- Prisma — migrations and schema/seed generation
- Kysely — type-safe database queries (types generated by the `prisma-kysely` plugin)
- Jest + Supertest — unit and e2e tests
- ESLint + Prettier

## Requirements

- Node.js 26 (the version used in CI)
- PostgreSQL 16 (or Docker to run it via `docker-compose`)

## Project Setup

1. Install dependencies:
   ```bash
   npm install
   ```

2. Create a `.env` file based on the example:
   ```bash
   cp .env.example .env
   ```
   and adjust values if needed (`DATABASE_URL`, etc.).

3. Start the PostgreSQL database. If you're using Docker, run:
   ```bash
   docker-compose up -d
   ```
   The container runs on port `5432` with database `db`, user `postgres`, and password `postgres`
   (see `docker-compose.yml`), matching the `DATABASE_URL` in `.env.example`.
   Otherwise, point `DATABASE_URL` in your `.env` to your own PostgreSQL instance.

4. Apply migrations, seed the database, and generate Kysely types:
   ```bash
   npm run setup
   ```
   This command runs `db:migrate`, `db:seed`, and `db:generate` in sequence.

## Running the Project

Development mode (with auto-restart):
```bash
npm run start:dev
```

Regular start:
```bash
npm run start
```

Production build:
```bash
npm run build
```

Once running, the server is available at `http://localhost:3000`, and Swagger docs at `http://localhost:3000/api`.

## Testing

Unit tests (custom validators, no database required):
```bash
npm test
```

End-to-end tests for all API endpoints:
```bash
npm run test:e2e
```

E2E tests need a running PostgreSQL instance (e.g. `docker-compose up -d`); nothing else has to be set up by hand:

- Tests use a separate `db_test` database configured in `.env.test`. It is created automatically,
  and migrations and the seed are applied before each run.
- Your development database is never touched: the tests refuse to run if the database name doesn't end with `_test`.
- Tests rely on the seed data (the `Wallet` and `Card` wallets and the default categories).
  Transactions are cleared and wallet balances are reset before every test.

## Code Style

Check linting and formatting (the same check runs in CI):
```bash
npm run lint
```

Fix issues automatically:
```bash
npm run lint:fix
```

Format `src` and `test` with Prettier:
```bash
npm run format
```

## Continuous Integration

GitHub Actions (`.github/workflows/test.yml`) runs on every push to `main` and on every pull request:
lint, type check, unit tests, and e2e tests against a PostgreSQL service container.
